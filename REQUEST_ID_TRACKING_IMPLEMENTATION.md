# Request ID Tracking Implementation

## Overview

Request ID tracking is fully implemented and operational in the Soroban Smart Block Explorer backend. Every HTTP request receives a unique identifier that flows through logs, error responses, and response headers for end-to-end request correlation.

## Implementation Status ✅ COMPLETE

All requirements from issue F4 are implemented and tested:

- ✅ **Unique UUID generation** per request using `crypto.randomUUID()`
- ✅ **Attached to req.requestId** in Express Request object
- ✅ **Added to response headers** (X-Request-Id)
- ✅ **Added to log entries** via AsyncLocalStorage context
- ✅ **Added to error responses** in response body and logs

## Architecture

### Middleware Stack

```
Request Flow:
├─ correlationMiddleware (src/middleware/correlation.ts)
│  ├─ Generate UUID or read x-request-id header
│  ├─ Attach to req.requestId
│  ├─ Set X-Request-Id response header
│  └─ Store in AsyncLocalStorage for context propagation
│
├─ Handler (access via req.requestId)
│  └─ Logs automatically include requestId
│
├─ Error Handler (src/middleware/errorHandler.ts)
│  ├─ Include requestId in error response body
│  └─ Log structured error with requestId
│
└─ Response
   ├─ X-Request-Id header for client correlation
   └─ requestId in error response body
```

### Core Components

#### 1. Correlation Middleware (`src/middleware/correlation.ts`)

Generates and manages request IDs:

```typescript
export function correlationMiddleware(req: Request, res: Response, next: NextFunction): void {
  // Generate or read request ID
  const requestId = (req.headers['x-request-id'] as string | undefined) ?? randomUUID();
  
  // Support OpenTelemetry B3 headers for distributed tracing
  let traceId = (req.headers['x-b3-traceid'] as string | undefined) ?? '';
  let spanId = (req.headers['x-b3-spanid'] as string | undefined) ?? '';
  
  // Attach to request
  req.requestId = requestId;
  req.traceId = traceId;
  req.spanId = spanId;
  
  // Set response header
  res.setHeader('X-Request-Id', requestId);
  
  // Store in AsyncLocalStorage for automatic context propagation
  const ctx: TraceContext = { requestId, traceId, spanId };
  traceStorage.run(ctx, next);
}
```

#### 2. Logger Integration (`src/logger.ts`)

Automatically includes request ID in all logs:

```typescript
function log(level: LogLevel, message: string, meta?: Record<string, unknown>): void {
  // Retrieve request context from AsyncLocalStorage
  const ctx = traceStorage.getStore();
  
  const entry: LogEntry = {
    level,
    message,
    timestamp: new Date().toISOString(),
    // Automatically add requestId if available
    ...(ctx?.requestId ? { requestId: ctx.requestId } : {}),
    // Include trace context for distributed tracing
    ...(ctx?.traceId ? { traceId: ctx.traceId } : {}),
    ...(ctx?.spanId ? { spanId: ctx.spanId } : {}),
    ...meta,
  };
  
  // Output in production JSON format or pretty format
  const line = IS_PROD ? JSON.stringify(entry) : prettyPrint(entry);
  if (level === 'error') process.stderr.write(line + '\n');
  else process.stdout.write(line + '\n');
}
```

#### 3. Error Handler (`src/middleware/errorHandler.ts`)

Includes request ID in error responses:

```typescript
export function errorHandler(err: Error, req: Request, res: Response, _next: NextFunction): void {
  const requestId = req.requestId ?? 'unknown';
  const statusCode = (err as AppError).statusCode ?? 500;
  const code = (err as AppError).code ?? 'INTERNAL_ERROR';
  
  // Build structured response with requestId
  const responseBody: StructuredErrorResponse = {
    error: err.message || 'Internal Server Error',
    code,
    requestId,  // ← Unique ID for this request
    statusCode,
  };
  
  // Log structured error
  logger.error('Unhandled server error', {
    requestId,
    code,
    statusCode,
    error: err.message,
    // ... additional context
  });
  
  res.status(statusCode).json(responseBody);
}
```

#### 4. Type Definitions (`src/types/express.d.ts`)

Request interface extended with tracking fields:

```typescript
declare global {
  namespace Express {
    interface Request {
      /** Unique ID for this HTTP request (correlation). */
      requestId?: string;
      /** OpenTelemetry / B3 trace ID propagated from upstream or generated by OTel. */
      traceId?: string;
      /** OpenTelemetry / B3 span ID of the root server span. */
      spanId?: string;
    }
  }
}
```

## Distributed Tracing

Request ID tracking integrates with OpenTelemetry and Zipkin (B3) headers for distributed tracing across microservices:

```typescript
// Middleware respects upstream trace context
const traceId = (req.headers['x-b3-traceid'] as string | undefined) ?? '';
const spanId = (req.headers['x-b3-spanid'] as string | undefined) ?? '';

// If not provided, generates new IDs
if (!traceId || !spanId) {
  const otelSpan = trace.getActiveSpan();
  if (otelSpan) {
    const sc = otelSpan.spanContext();
    traceId = traceId || sc.traceId;
    spanId = spanId || sc.spanId;
  }
}

// Propagates through AsyncLocalStorage
const ctx: TraceContext = { requestId, traceId, spanId };
traceStorage.run(ctx, next);
```

```typescript

```

## Best Practices

### ✅ Do's

1. **Access request ID directly** when needed
```typescript
const id = req.requestId;
```

2. **Let logs automatically include request ID**
```typescript
logger.info('Processing', { data: value });
// requestId is automatically added
```

3. **Use request ID for user-facing errors**
```typescript
res.status(500).json({
  error: 'Internal server error',
  requestId: req.requestId,
  help: 'Contact support with this request ID'
});
```

4. **Pass request ID to external APIs**
```typescript
await externalService.call({
  // ... payload
  requestId: req.requestId  // For tracing on their end
});
```

### ❌ Don'ts

1. **Don't generate custom IDs** - let middleware handle it
2. **Don't forget to include in error messages** - helps users report issues
3. **Don't lose request ID context** - use AsyncLocalStorage for propagation
4. **Don't skip B3 headers** - they enable distributed tracing

## Troubleshooting

### Issue: Request ID not appearing in logs

**Solution:** Ensure `correlationMiddleware` is registered before other middleware:
```typescript
app.use(correlationMiddleware);
// Other middleware after this
```

### Issue: Request ID not in response header

**Cause:** Custom response handling bypassing standard middleware
**Solution:** Ensure correlationMiddleware is not skipped for the route

### Issue: Request ID undefined in handler

**Cause:** Middleware chain interrupted
**Solution:** Check for try/catch or error handling that breaks the chain
